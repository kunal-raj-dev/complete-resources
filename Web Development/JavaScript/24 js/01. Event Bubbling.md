## 1. Mental Model & Concept Overview

### 💡 Simple Definition (Kya hota hai Event Bubbling?)
Jab hum kisi **nested (andar wale) HTML element** par koi event (jaise `click`) trigger karte hain, toh woh event sirf usi element tak seemit nahi rehta. Woh event ek **paani ke bulbule (bubble)** ki tarah apne parent, grandparent aur pure DOM tree ke top tak **upar ki taraf travel** karta hai.

Isi upward propagation (upar travel karne) ko hum **Event Bubbling** kehte hain.

```
       [ window ]
           ▲
      [ document ]
           ▲
       [ <body> ]
           ▲
        [ <div> ]       <-- Parent
           ▲
        [ <ul> ]        <-- Child
           ▲
        [ <li> ]        <-- Target (Clicked here! Event bubbles UP 🫧)
```

### 🎯 Real-Life Analogy
- **Ghar ka Example:** Agar ek kamre ke andar koi chhota bacha shor machata hai, toh pehle kamre mein aawaz aayegi (child), fir hall mein aawaz sunai degi (parent), aur fir pure ghar/building mein aawaz jayegi (grandparent).
- **Carbonated Soda Bubble:** Glass ke bottom se gas bubble banta hai aur dheere-dheere surface (top) ki taraf nikal jata hai.

## 2. The Big Picture: Event Propagation Lifecycle (3 Phases)

W3C / DOM Standards ke mutabiq, jab bhi koi event occur hota hai, toh browser **3 phases** execute karta hai:

```mermaid
flowchart TD
    subgraph Phase 1: Capturing Phase (Trickling Down)
        W[window] --> D[document]
        D --> B[body]
        B --> Div[div]
        Div --> Ul[ul]
    end

    subgraph Phase 2: Target Phase
        Ul --> Li["li (Target Element)"]
    end

    subgraph Phase 3: Bubbling Phase (Rising Up)
        Li -.-> Ul2[ul]
        Ul2 -.-> Div2[div]
        Div2 -.-> B2[body]
        B2 -.-> D2[document]
        D2 -.-> W2[window]
    end

    style Li fill:#f9f,stroke:#333,stroke-width:3px
```

| Phase | Name | Direction | Default Listener State |
| :--- | :--- | :--- | :--- |
| **Phase 1** | **Capturing Phase** (Trickling) | Top se Down (`window` $\rightarrow$ Target) | Inactive (by default) |
| **Phase 2** | **Target Phase** | On the actual element clicked | Active |
| **Phase 3** | **Bubbling Phase** | Bottom se Up (Target $\rightarrow$ `window`) | **Active by default** |

> 📌 **Important Note:** JavaScript ka `addEventListener(type, listener)` by default **Bubbling Phase** mein trigger hota hai, kyunki iska 3rd argument `useCapture` by default `false` hota hai.

### Execution Flow (What happens on click?)

#### Case 1: Clicking directly on `div` (Pink Area)
- **Target:** `div`
- **Output:**
  ```
  div was clicked
  ```
- **Reason:** `div` ke upar `body` aur `document` hain, par unpe koi click listener nahi laga hai. Aur `div` ke niche `ul` ya `li` hain, par bubbling upar jati hai, niche nahi!

---

#### Case 2: Clicking on `ul` (Blue Area)
- **Target:** `ul`
- **Output:**
  ```
  ul was clicked
  div was clicked
  ```
- **Reason:** Event `ul` se bubble hoke uske parent `div` par chala gaya! Dono ke listeners execute ho gaye.

---

#### Case 3: Clicking on `li` (Greenyellow Area)
- **Target:** `li`
- **Output:**
  ```
  li was clicked
  ul was clicked
  div was clicked
  ```
- **Reason:** 
  1. `li` ka listener chala.
  2. Event bubble hoke parent `ul` par gaya $\rightarrow$ `ul` ka listener chala.
  3. Event aur upar bubble hoke grandparent `div` par gaya $\rightarrow$ `div` ka listener chala.

## 4. Fixing the Issue: `event.stopPropagation()`

Kayi baar hum chahte hain ki agar user ne `li` par click kiya hai, toh **sirf aur sirf `li` ka action trigger ho**, parent ka action trigger na ho (e.g. Card click karne se modal khulna chahiye, lekin card ke andar 'Delete' button click karne se sirf delete hona chahiye, modal nahi khulna chahiye).

Iske liye JavaScript humein Event Object par ek method deta hai: **`event.stopPropagation()`**.

### Updated `app.js` (With `stopPropagation`)
```javascript
let div = document.querySelector("div");
let ul = document.querySelector("ul");
let lis = document.querySelectorAll("li");

div.addEventListener("click", function (event) {
    // event.stopPropagation(); // Agar zarurat ho
    console.log("div was clicked");
});

ul.addEventListener("click", function (event) {
    event.stopPropagation(); // Stops event from bubbling to div
    console.log("ul was clicked");
});

for (let li of lis) {
    li.addEventListener("click", function (event) {
        event.stopPropagation(); // Stops event from bubbling to ul & div
        console.log("li was clicked");
    });
}
```

### Result After Fix:
- Click on `li` $\rightarrow$ Console: `li was clicked` *(ul aur div par nahi gaya)*
- Click on `ul` $\rightarrow$ Console: `ul was clicked` *(div par nahi gaya)*
- Click on `div` $\rightarrow$ Console: `div was clicked`

## 5. Topper's Additional Context (Interview & Production Essentials)

Video mein basic bubbling aur `stopPropagation()` cover hua hai. Ek **topper / senior developer** ki tarah sochte hue, yahan woh deep concepts hain jo interviews aur large-scale codebases mein 100% puche jate hain:

---

### A. `stopPropagation()` vs `stopImmediatePropagation()`

Ye ek bahut popular tricky interview question hai:

```javascript
element.addEventListener("click", function(e) {
    e.stopPropagation();
    console.log("Listener 1 executed");
});

element.addEventListener("click", function(e) {
    console.log("Listener 2 executed");
});
```

- **`e.stopPropagation()`**: Yeh event ko **DOM tree ke upar (parents ko) jane se rokta hai**, lekin **isi same element ke baki listeners ko execute hone deta hai**! Isliye dono `Listener 1` aur `Listener 2` chalenge.
- **`e.stopImmediatePropagation()`**: Yeh event ko parents tak jane se bhi rokta hai AUR **isi element ke baki bache hue event listeners ko bhi turant block kar deta hai**! Agar Listener 1 mein `stopImmediatePropagation()` hota, toh Listener 2 chalta hi nahi.

| Method | Stops Parents? | Stops Other Listeners on SAME Element? |
| :--- | :---: | :---: |
| `event.stopPropagation()` | ✅ Yes | ❌ No |
| `event.stopImmediatePropagation()` | ✅ Yes | ✅ Yes |

---

### B. `event.target` vs `event.currentTarget`

Jab event bubble hota hai, toh do properties bahut crucial hoti hain:

```javascript
div.addEventListener("click", function(event) {
    console.log("Target:", event.target);
    console.log("CurrentTarget:", event.currentTarget);
    console.log("this:", this);
});
```

Agar user ne `<li>` par click kiya aur event bubble hoke `<div>` par aaya:
1. **`event.target`**: Woh element jahan se event **origin (start)** hua tha $\rightarrow$ `<li style="background: greenyellow">one</li>`.
2. **`event.currentTarget`** (or `this`): Woh element jiska **listener abhi execute ho raha hai** $\rightarrow$ `<div>`.

> 💡 **Pro Tip:** In Event Delegation, `event.target` is what you inspect to know exactly which child was clicked!

---

### C. `stopPropagation()` vs `preventDefault()`

Dono alag-alag cheezein hain, inhe mix mat karna:

- **`event.preventDefault()`**: Browser ka **default behavior** rokta hai.
  - Form submit hone par page reload hona roknā.
  - Link (`<a href="...">`) click karne par naye page pe redirect hona roknā.
  - Checkbox click hone par check/uncheck hona roknā.
  - *Does NOT stop bubbling!*
- **`event.stopPropagation()`**: Event ka **DOM tree mein travel (propagation)** rokta hai.
  - *Does NOT stop default browser behavior!*

---

### D. Capturing Phase in Action (`{ capture: true }`)

Agar hum chahein ki parent pehle chale aur child baad mein, toh hum listener ko **Capturing Phase** mein activate kar sakte hain:

```javascript
div.addEventListener("click", function() {
    console.log("DIV (Capturing)");
}, { capture: true }); // Ya simply true pass kar sakte hain

li.addEventListener("click", function() {
    console.log("LI (Clicked)");
});
```

**Output when clicking `li`:**
```
DIV (Capturing)    <-- Parent ran first because it caught event on the way down!
LI (Clicked)       <-- Target ran second
```

### E. Events That DO NOT Bubble

Har event bubble nahi hota! Interviewers aksar poochte hain: *"Name 3 events that do not bubble."*

| Events that DO NOT Bubble | Bubbling Alternative | Use Case |
| :--- | :--- | :--- |
| `focus` | `focusin` | Input field focus hone par |
| `blur` | `focusout` | Input field se focus hatne par |
| `mouseenter` | `mouseover` | Mouse element ke upar aane par |
| `mouseleave` | `mouseout` | Mouse element se bahar jane par |
| `load`, `unload` | — | Window/document load events |
| `scroll` *(on elements)* | — | Element scrolling |

## 6. Real-World Bug Case Study: Modal / Backdrop Click

### ❌ The Bug:
Aapne ek Modal banaya jisme backdrop (black overlay) click karne par modal close hona chahiye.
Lekin jab user modal ke **andar kisi text box ya button** par click karta hai, tab bhi modal band ho jata hai!

```html
<div class="modal-backdrop" onclick="closeModal()">
    <div class="modal-content">
        <h2>Terms & Conditions</h2>
        <button onclick="acceptTerms()">Accept</button>
    </div>
</div>
```

### 🔍 Why it happens?
Modal content par click karne par event bubble hoke `.modal-backdrop` tak chala jata hai, aur `closeModal()` trigger ho jata hai!

### ✅ The Fix:
```javascript
const modalContent = document.querySelector(".modal-content");

modalContent.addEventListener("click", function(e) {
    e.stopPropagation(); // Ab modal ke content pe click karne se backdrop trigger nahi hoga!
});
```

## 7. Connection to Next Topic: Event Delegation

Kya Event Bubbling sirf ek "problem" hai jisko `stopPropagation()` se theek karna padta hai?
**Nahi! Event Bubbling JavaScript ka ek bohot bada SUPERPOWER hai.**

Kyunki events bubble hoke parent tak aate hain, humein 100 alag-alag `<li>` buttons par listeners lagane ki zarurat nahi hoti. Hum sirf ek single listener unke parent `<ul>` par laga sakte hain aur `event.target` se identify kar sakte hain ki kaunsa child click hua.

Is powerful pattern ko **Event Delegation** kehte hain, jo ki agla lecture hai!

## 8. Summary & Quick Revision Cheatsheet

| Concept | Explanation |
| :--- | :--- |
| **Event Bubbling** | Event propagates from bottom (child) $\rightarrow$ top (ancestors/window). |
| **Event Capturing** | Event travels from top (window) $\rightarrow$ bottom (target). Trickling. |
| **Default Phase** | JS event listeners run in **Bubbling Phase** by default. |
| **`e.stopPropagation()`** | Stops the event from traveling further up or down the DOM. |
| **`e.stopImmediatePropagation()`** | Stops event bubbling + disables other listeners on current element. |
| **`e.preventDefault()`** | Stops browser default action (e.g. form submit, link navigate). |
| **`e.target`** | Element that triggered the event (the origin). |
| **`e.currentTarget`** | Element attached to the currently executing listener (`this`). |

## 9. Frequently Asked Interview Questions (Q&A)

### Q1: What is the difference between Event Bubbling and Event Capturing?
> **Answer:** Event Capturing (Trickling) mein event window se start hoke target element ki taraf niche travel karta hai. Event Bubbling mein event target element se start hoke parent elements aur window ki taraf upar travel karta hai. W3C model mein Capturing pehle hoti hai, fir Target phase, aur fir Bubbling phase.

### Q2: What does `event.stopPropagation()` do? Does it stop all handlers?
> **Answer:** `event.stopPropagation()` prevents the event from bubbling up to parent elements in the DOM tree. However, it does NOT stop other listeners attached to the exact same element from executing. To stop subsequent listeners on the same element, we use `event.stopImmediatePropagation()`.

### Q3: How do you enable Event Capturing in `addEventListener`?
> **Answer:** By passing `{ capture: true }` or simply `true` as the third argument to `addEventListener`:
> ```javascript
> element.addEventListener("click", handler, true);
> ```

### Q4: Why would you NOT want to use `stopPropagation()` everywhere?
> **Answer:** Overusing `stopPropagation()` breaks **Event Delegation**, analytics/tracking scripts (e.g., Google Analytics tracking page clicks), and UI frameworks or libraries that rely on document-level event listeners. It should be used deliberately only where needed.
