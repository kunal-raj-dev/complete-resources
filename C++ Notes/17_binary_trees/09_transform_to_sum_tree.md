## 🧠 Core Intuition — Why This Works
To transform a tree into a sum tree, every node needs to know the sum of its children's subtrees. We can't calculate this top-down because a parent doesn't know what its children's sums are yet. Therefore, we must work bottom-up using **Post-order Traversal** (Left, Right, Root).

Each node must do two things:
1. Update its own value to be the sum of its left and right subtrees.
2. Tell its parent the sum of its *entire* original subtree (which is its old value + its new value).

*Analogy:* Imagine a corporate hierarchy where each manager must replace their own net worth with the total revenue generated by their direct reports and teams below them. A manager asks their left and right team leads for their total department revenues. The manager saves their own original revenue, replaces their revenue with the sum of the leads' reports, and then passes up their (original + new) revenue to their boss.

## 🎯 Pattern Recognition — When to Use This
- **Trigger cues:** "modify in-place", "sum of subtree", "bottom-up dependency".
- **Pattern:** Post-order DFS. Any time a node's state depends entirely on the aggregated states of its descendants, post-order traversal is the required pattern.

## 📐 Algorithm Walk-Through
1. **Base Case:** If the current node is `nullptr`, it contributes `0` to the sum. Return `0`.
2. **Save State:** Store the current node's value in a temporary variable `oldVal`.
3. **Recursive Calls (Post-order):**
   - Call `toSumTree(root->left)` and store in `leftSum`.
   - Call `toSumTree(root->right)` and store in `rightSum`.
4. **Mutate:** Update `root->val = leftSum + rightSum`.
5. **Return:** Return `oldVal + root->val` (which represents the total sum of this entire subtree including the original node) to the parent caller.

## 🔵 State Transformation Invariant
For every node $u$:
$$\text{newVal}(u) = \text{sumTree}(u.\text{left}) + \text{sumTree}(u.\text{right})$$
$$\text{returnValue}(u) = \text{oldVal}(u) + \text{newVal}(u)$$
- Leaves have empty left and right subtrees; their new value becomes $0 + 0 = 0$, and they return their original leaf value.

```text
Original Tree:
        10
       /  \
     -2    6
     / \  / \
    8  -4 7  5

Transformed Sum Tree:
        20           // (-2 + 8 - 4) + (6 + 7 + 5) = 2 + 18 = 20
       /  \
      4    12        // (8 - 4) = 4, (7 + 5) = 12
     / \  / \
    0   0 0  0       // Leaves become 0
```

## 💻 Complete C++ Implementation

```cpp
#include <iostream>

using namespace std;

struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

class SumTreeTransformer {
public:
    // Returns total subtree sum (oldVal + newVal)
    static int toSumTree(TreeNode* root) {
        if (!root) return 0;

        int oldVal = root->val;

        // Post-order: compute left and right subtree sums first
        int leftSum = toSumTree(root->left);
        int rightSum = toSumTree(root->right);

        // Update current node with sum of left and right subtrees
        root->val = leftSum + rightSum;

        // Return total sum to parent: original value plus all descendants
        return oldVal + root->val;
    }

    static void printInorder(TreeNode* root) {
        if (!root) return;
        printInorder(root->left);
        cout << root->val << " ";
        printInorder(root->right);
    }
};

int main() {
    TreeNode* root = new TreeNode(10);
    root->left = new TreeNode(-2);
    root->right = new TreeNode(6);
    root->left->left = new TreeNode(8);
    root->left->right = new TreeNode(-4);
    root->right->left = new TreeNode(7);
    root->right->right = new TreeNode(5);

    SumTreeTransformer::toSumTree(root);

    cout << "Inorder of Transformed Sum Tree: ";
    SumTreeTransformer::printInorder(root); // Output: 0 4 0 20 0 12 0
    cout << endl;
    return 0;
}
```

## 🔍 Dry Run Trace
Let's trace the left subtree of the root: `Node(-2)` with children `8` and `-4`.
- `toSumTree(-2)` is called. `oldVal` = -2.
  - Calls `toSumTree(8)` (left child):
    - `oldVal` = 8.
    - `leftSum` = `toSumTree(null)` = 0.
    - `rightSum` = `toSumTree(null)` = 0.
    - Update: `node->val` = 0 + 0 = 0.
    - Returns: 8 + 0 = 8.
  - `leftSum` for `-2` is now 8.
  - Calls `toSumTree(-4)` (right child):
    - Similarly, updates to 0, returns -4.
  - `rightSum` for `-2` is now -4.
  - Mutate Node `-2`: `val` = `leftSum` (8) + `rightSum` (-4) = 4.
  - Return to root (`10`): `oldVal` (-2) + `newVal` (4) = 2.
This correctly computes the left subtree sum (2) for the root's calculation.

## ⚠️ Common Interview Mistakes
1. **Returning just `root->val`:** The parent needs the sum of the *entire* original subtree. If you return `root->val`, you are missing the node's original value which is part of the sum for its parent. You must return `oldVal + root->val`.
2. **Forgetting to store `oldVal`:** If you do `root->val = leftSum + rightSum` and then return `root->val + root->val`, it's completely wrong. The original value is lost.
3. **Using Pre-order:** You cannot calculate the subtree sum before you have visited the subtrees. It must be post-order.

## ⏱️ Complexity Analysis
- **Time Complexity:** $O(N)$. Each node is visited exactly once during the post-order traversal. At each node, we perform $O(1)$ operations (addition and assignment).
- **Space Complexity:** $O(H)$ where $H$ is the height of the tree. This is the space used by the recursion stack. In a skewed tree, it's $O(N)$; in a balanced tree, it's $O(\log N)$.

## 🔥 Interview Q&A
### Q1: What if the problem asked to NOT modify the leaf nodes?
You would add an explicit base case to check if a node is a leaf (both left and right are null). If so, you simply return its value without modifying it.
```cpp
if (!root->left && !root->right) return root->val;
```

### Q2: How can we verify if a given binary tree is ALREADY a Sum Tree?
To check if a tree is a sum tree, you write a recursive function that returns the sum of the subtree if it is a valid sum tree, and a special value (like `INT_MIN`) if it isn't. At each node, you verify that `root->val == left_sum + right_sum` (except for leaves). If the condition fails at any point, bubble up `INT_MIN`.

### Q3: Why is post-order traversal uniquely suited for this?
Because in post-order (Left, Right, Root), we process all descendants of a node *before* processing the node itself. A node needs the aggregated data (sums) from its children to compute its own new value. Pre-order and In-order would process the parent before at least one of its children, making the aggregation impossible without multiple passes.

### Q4: Could this be done iteratively?
Yes, using an iterative post-order traversal (which typically requires two stacks or one stack with a `lastVisited` pointer). You would also need a way to map nodes to their computed sums (like a hash map), making the iterative approach much more verbose and requiring $O(N)$ extra space for the map. Recursion is far more elegant here.

### Q5: Can this approach handle negative numbers?
Yes. The addition `leftSum + rightSum` perfectly handles negative numbers. The logic of summing subtrees does not depend on the sign of the node values.

## ⚡ 2-Minute Revision Flash Card
- **Goal:** Replace each node's value with sum of its left and right subtrees.
- **Traversal:** Post-order DFS (Bottom-Up).
- **Core Logic:**
  - `int oldVal = root->val;`
  - `left = call(root->left);`
  - `right = call(root->right);`
  - `root->val = left + right;`
  - `return oldVal + root->val;`
- **Time:** $O(N)$.
- **Space:** $O(H)$ recursion stack.
- **Trap:** Forgetting to save the original value before mutating, which is required to pass the correct sum up to the parent.
